A: Branches on Sides

Move then to left, keep else on right, bottom becomes "next" (continuation). Bottom always means "what comes next" in the vertical flow.

Pros

  • Strongest spatial metaphor: down = sequence
  • Matches Unreal Blueprints, Node-RED conventions
  • Clear visual grammar across all containers

Cons

  • Breaking change to existing IF layout
  • Branch children flow sideways, not down
  • Wider canvas usage

B: Bar Below Existing

Keep current layout (bottom circle = then, right = else). Add a distinct bar-shaped handle below the circle with a small gap. Different shape = different meaning.

Pros

  • No breaking changes to existing flows
  • Shape difference (bar vs circle) is immediately visible
  • Vertical flow preserved for branch children

Cons

  • Two things stacked at bottom could confuse new users
  • "Down" means two different things (branch vs continue)
  • More vertical space per container block

C: Diamond Handle, Bottom-Left (recommended)

Keep existing layout. Add a diamond-shaped handle at the bottom-left corner. Different shape and different position = zero ambiguity.

Pros

  • No breaking changes
  • Shape + position both differ from branch handles
  • Diamond universally reads as "decision resolved / merge point"
  • Bottom-left keeps it out of the way of branch edges

Cons

  • Slightly asymmetric visual
  • Small handle could be hard to click (mitigated by making hitbox larger)

Best Practices for Clarity in Node Editors

  • Shape encodes meaning — circle = branch/flow, diamond = merge/decision, bar = terminator. Users learn the grammar once and apply it everywhere.
  • Position encodes direction — bottom = down = "next in sequence", side = "alternative path". Mixing meanings at the same position forces users to read labels.
  • Consistency across block types — if every container uses the same handle shape/position for "continue", users build muscle memory fast.
  • Minimal reliance on labels — the handle should be self-explanatory from shape and position alone. Labels are confirmation, not primary signal.
