Connection Model: Structured Flow with Expandable Containers

SSH scripts are sequential step lists — not free-form graphs. The visual model reflects this: blocks flow top-to-bottom with edges, and control flow blocks are container nodes that expand to reveal their sub-flows.

Block Anatomy — Every Block Has

● Flow-in port (top center) — connects from previous step
● Flow-out port(s) (bottom) — connects to next step(s)
● Category badge — color-coded type label
● Label — user-editable display name
● Preview — compact view of key params (command text, condition, pattern)
● Breakpoint gutter — click to toggle red breakpoint dot
● Execution state — idle / running (glow) / success (green) / error (red)
● on_error badge — shows error handling mode if set

Properties Panel — Click Any Block to Edit

When you select a block, a side panel shows all configurable properties for that command type. Each block type has its own property schema derived from the ScriptParser's YAML key definitions. For example, a SEND block shows: command text, timeout override, on_error handling, expect patterns, delay. An EXTRACT block shows: pattern (regex), source, variable name, match options.
