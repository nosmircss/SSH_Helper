Flow Canvas — Technical Approach

Three options for the node graph engine inside WebView2. Click your preference.

A

React Flow (Recommended)

The most popular and visually polished node editor library (37k+ GitHub stars). Used by Stripe, Typeform, and many production tools.

Pros

  • Best visual quality — smooth animations, curved edges, polished UX
  • Custom nodes are React components — easy to build 35 block types
  • Built-in: minimap, zoom/pan, snap-to-grid, selection, keyboard shortcuts
  • Auto-layout via dagre/elkjs — critical for YAML → visual import
  • Active ecosystem, excellent docs, MIT license

Cons

  • Requires build step (Vite + React → static bundle)
  • Heavier bundle (~200KB gzipped)
  • React dependency (isolated inside WebView2, doesn't affect WinForms)
Why I recommend this: Maximum wow factor. The build step is a one-time setup — we'd bundle the compiled assets as embedded resources in the WinForms project. React components make it natural to create rich, interactive block types with property editors, validation states, and execution animations.
B

LiteGraph.js

Powers ComfyUI (Stable Diffusion). Battle-tested for visual programming with a built-in execution model. Vanilla JavaScript.

Pros

  • Purpose-built for visual programming (not just diagrams)
  • No framework dependency — vanilla JS, single file include
  • Built-in node execution model, type system, serialization
  • Proven at scale (ComfyUI has millions of users)

Cons

  • More utilitarian aesthetic — "ComfyUI look" vs polished product feel
  • Canvas2D rendering (vs DOM) — harder to add rich HTML inside nodes
  • Customization requires deeper library knowledge
  • Less active community than React Flow
C

Custom SVG Engine

Build a bespoke node editor from scratch using SVG and vanilla JavaScript. Full control over every pixel.

Pros

  • Perfect visual match with SSH Helper's design language
  • Zero dependencies — lightest possible bundle
  • Complete control over interactions and animations

Cons

  • Massive engineering effort — reimplementing zoom, pan, drag, selection, connection management, auto-layout
  • Every UX detail must be hand-crafted (what libraries give for free)
  • Higher bug surface area in core interactions
  • Months of work vs weeks

Architecture (same for all approaches)

FlowCanvasForm (WinForms Window)
└── WebView2 Control
    └── Node Graph App (bundled HTML/JS/CSS)
         ├── Block Palette (collapsible sidebar)
         ├── Canvas (node graph engine)
         │    ├── Custom Block Components (one per command type)
         │    ├── Connection Edges (animated during execution)
         │    ├── Minimap + Zoom Controls
         │    └── Context Menus (right-click)
         ├── Variable Inspector (overlay panel)
         ├── Debug Panel (breakpoints, call stack, controls)
         └── Properties Panel (edit selected block's settings)

Communication via WebView2 PostWebMessage:
  WinForms → WebView2:  LoadScript(yaml), ExecutionUpdate(), DebugState()
  WebView2 → WinForms:  ApplyToYaml(), RunRequest(), DebugAction()
