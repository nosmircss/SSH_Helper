Key Design Decisions

New WinForms Files
FlowCanvasForm.cs — WebView2 host window, size/position memory, modeless like InteractiveTerminalForm

FlowCanvasBridge.cs — Service that converts between YAML ↔ JSON graph format, pipes execution/debug events to WebView2
Reused Existing Code
ScriptParser — Already parses YAML → Script model. We convert Script → graph JSON

DebugState — Already has breakpoints, step/pause/continue. Bridge connects to canvas

BrowserCallbackWebViewDialog — Existing WebView2 hosting pattern to follow
New React Project
FlowCanvas/ — Separate directory in repo root
Vite + React + TypeScript + React Flow
npm run build → dist/ folder
Built assets copied to WinForms embedded resources
Message Protocol
JSON messages over PostWebMessage:
{ type: "load-script", yaml: "..." }
{ type: "execution-update", stepId, state }
{ type: "apply-yaml", yaml: "..." }
{ type: "debug-action", action: "step" }

User Flow

Opening: User clicks "Flow Canvas" button (in script header or menu) → FlowCanvasForm opens → loads current YAML from script editor → renders as visual graph

Building: Drag blocks from palette → configure in properties panel → connect outputs to inputs → graph validates connections in real-time

Debugging: Click breakpoint gutter on any block → Run from canvas → execution animates through blocks → pauses at breakpoints → inspect variables → step/continue

Applying: Click "Apply to YAML" → graph converts back to YAML → script editor updates → canvas closes (or stays open, read-only)
