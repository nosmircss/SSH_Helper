Section 3: YAML ↔ Graph Conversion

YAML → Graph (Import)
Input: YAML Script
steps:
  - send: show version
    name: Get Version
  - extract:
      pattern: "Version (\S+)"
      into: firmware_ver
  - if:
      condition: firmware_ver != "17.9.5"
      then:
        - print: ⚠ Outdated
      else:
        - print: ✓ Current
→
Conversion Pipeline
1. ScriptParser.Parse(yaml)
Existing C# parser → Script model with steps[]
2. FlowCanvasBridge.ToGraph(script)
New C# → walks step tree, generates node[] + edge[] JSON
3. PostWebMessage({ type: "load-graph", nodes, edges })
Send to WebView2
4. React Flow auto-layout (dagre/elkjs)
Position nodes in clean top-to-bottom flow
Graph → YAML (Export / Apply)
1. User clicks "Apply to YAML"
→
2. React app serializes graph to JSON
(nodes with properties + edges with connections)
→
3. PostWebMessage → FlowCanvasBridge
→
4. FlowCanvasBridge.ToYaml(graph)
Walks node tree, generates clean YAML
→
5. Script editor receives YAML text
Round-trip guarantee: YAML → Graph → YAML should produce functionally identical YAML. The bridge preserves: step ordering, nesting depth, all property keys, comments (stored as metadata on graph nodes), and formatting preferences.

Section 4: Full Debugger Integration

The existing DebugState in ScriptExecutor already supports breakpoints, step-mode, pause/continue/step signals. FlowCanvasBridge acts as the visual frontend for this infrastructure.

Debug Message Flow
User clicks breakpoint on EXTRACT block
  Canvas → PostWebMessage → FlowCanvasBridge
    → DebugState.AddBreakpoint(stepIndex: 2)     // existing API

User clicks ▶ Run in canvas
  Canvas → PostWebMessage → FlowCanvasBridge
    → SshExecutionService.ExecuteScriptAsync()  // existing API
    → DebugState.IsEnabled = true               // enables debug mode

Execution reaches SEND block (step 1)
  ScriptExecutor fires step-begin event
    → FlowCanvasBridge → PostWebMessage
      → Canvas highlights SEND node with blue glow + "RUNNING"

SEND completes, EXTRACT step begins → hits breakpoint
  DebugState pauses execution (existing pause mechanism)
    → FlowCanvasBridge → PostWebMessage:
      {
        type: "debug-paused",
        stepId: "extract-1",
        variables: { firmware_ver: null, output: "Cisco IOS..." },
        callStack: ["main:2 extract 'Parse Version'", "main:1 send 'Get Version'"],
        nextStepPreview: "if: firmware_ver != '17.9.5'"
      }

    → Canvas shows:
      • Red breakpoint indicator on EXTRACT block
      • Green "completed" on SEND block
      • Variable inspector updates with current values
      • Call stack panel updates

User clicks "Step Over" in canvas
  Canvas → PostWebMessage → FlowCanvasBridge
    → DebugState.StepSignal.Set()               // existing API
    → Execution advances one step
    → Next pause event fires → canvas updates

User clicks "Continue"
  Canvas → PostWebMessage → FlowCanvasBridge
    → DebugState.ContinueSignal.Set()           // existing API
    → Execution runs until next breakpoint or completion
    → Each step fires begin/end events → canvas animates through

What We Reuse (Existing)

  • DebugState — breakpoints, step/pause/continue signals
  • ScriptParser — YAML → Script model
  • ScriptExecutor — step-level events during execution
  • SshExecutionService — ExecuteScriptAsync entry point
  • BrowserCallbackWebViewDialog — WebView2 hosting pattern
  • ScriptContext.Variables — variable state for inspector

What We Build New

  • FlowCanvasForm — WinForms window with WebView2
  • FlowCanvasBridge — YAML↔Graph + event piping service
  • Step ID mapping — maps script step indices ↔ graph node IDs
  • React Flow app — canvas, palette, properties, debug panels
  • 35 block definitions — node components + property schemas
  • Graph → YAML generator — JS-side serializer

Debugger Features Summary

● Click block gutter → toggle breakpoint (red dot)
● Conditional breakpoints (right-click → set condition)
● Step Over — advance one step, skip into containers
● Step Into — enter container blocks (if, while, etc.)
● Continue — run until next breakpoint
● Stop — cancel execution
● Variable inspector — live values, expandable objects
● Call stack — shows current nesting path
● Execution trace — blocks glow as they execute
● Error highlighting — failed block turns red with tooltip
