## Feature inventory

### 1. Job dashboard — `JobListDialog` ("Scheduled Jobs")
Entry: Form1 menu item "&Scheduler" → `Form1.ShowJobListDialog()` (Form1.cs:15135, 15164–15195), shown **modeless single-instance** via `_jobListDialogManager.ShowOrActivate` (ModelessDialogManager). Also reachable from the scheduler status-bar link area (Form1.cs:15143–15146 timer block).

Split layout: jobs grid on top (60% on load, JobListDialog.cs:157), run-history grid for the selected job below.

- **Jobs grid** (BuildJobGrid, :293–358): columns Name / On (checkbox) / Schedule / Next Run / Last Result / Target. `MultiSelect = false` (:303). Row `Tag` = job id. Running job name rendered lime/green (:537–543); disabled jobs greyed (:546–551). Target display: `[F] name` for folders, `[Custom] Scheduler-local content` for custom presets (:518–523).
- **Schedule/next-run text** (:724–753): cron description via `SchedulingService.GetDescription`, next run via `GetNextRunLocal`; One-Time shows local time or "Completed" once past; disabled → "Disabled"; manual → "On demand"/"-".
- **Last Result** (:755–763): loads `JobHistoryService.GetRunsForJob(job.Id, MaxResults=1)` per job per refresh. Result vocabulary in `GetRunResultText` (:923–946): `OK (s/t)`, `FAIL (s/t)`, `FAIL x{n} (s/t)` using `ConsecutiveFailureCount`, `CANCELLED (s/t)`, `SKIPPED`/`SKIPPED (n)` for downtime-summary records.
- **Toolbar + context menu** (BuildToolStrip :191, BuildContextMenu :232): New, Edit, Run Now, Cancel, Enable/Disable, Delete, Duplicate, Export File, Export Clipboard, Import File, Import Clipboard. Enablement in `UpdateJobActionState` (:886–904) — Run Now disabled while running, Cancel enabled only while running.
- **Keyboard** (OnKeyDown :1006–1027, only when jobs grid focused): Delete = delete job, Enter/F2 = edit, F5 = refresh. Double-click row = edit (:971). Clicking the "On" checkbox cell toggles enabled state inline (:985–998 → `ToggleJobEnabled` :1273, clears `DisabledReason` when re-enabling).
- **Live refresh**: 5-second `Timer` full rebuild (:179–180) **plus** event-driven refresh from `JobStorageService.JobsChanged`, `JobExecutionService.JobStateChanged`, `JobExecutionService.JobCompleted` (:433–435), all marshaled via `BeginInvoke` (:457–485). Selection survival is hand-rolled: `_selectedJobId` / `_selectedHistoryRunFileName` + `SelectActiveJob`/`SelectActiveHistoryRun` (:566–878) with suppression flags. Events unsubscribed and timer disposed on FormClosing (:445–455).
- **Run Now** (:1061–1076): async; routed through `_runNowInvoker` delegate when provided (Form1 passes `RunTrackedJobNowAsync`) else `JobExecutionService.RunNowAsync` (:1515–1523). Failure shows "may already be running" warning.
- **Cancel** (:1078–1094): `JobExecutionService.CancelJob`, info box if not running.
- **Duplicate** (:1109–1138): JSON deep clone, new `Guid.NewGuid("N")` id, name + " (copy)", resets `RunningState`; copies the stored Credential Manager secret to the new job's target with rollback (`SaveDuplicatedJob` :1295–1308 deletes the duplicate via `Delete(id, cleanupCredentials:false)` if credential copy throws).
- **Delete** (:1369–1385): confirm via `DialogTheme.Confirm`, then `JobStorageService.Delete(jobId)` (default `cleanupCredentials:true`, JobStorageService.cs:147–158 also deletes the CredMan secret) + `JobHistoryService.DeleteAllHistory(jobId)`.
- **Export** (:1140–1197): `.sshjobs` JSON file or GZip+Base64 clipboard string via `JobExportService` (Services/JobExportService.cs). Default filename = job name for 1 job, "exported-jobs" for many.
- **Import** (:1199–1242 → `ProcessImportedJobs` :1420–1463): file or clipboard → `JobExportService.PrepareImport` (name-conflict rename), dialog computes `MissingTarget` by checking `PresetManager.Presets`/`Folders` (:1437–1450) → `ImportPreviewDialog` → `CommitImportedEntries` (:1465, `internal static` for tests) saves each job, applying `SchedulerJobIntegrityUtilities.ApplyMissingTargetImportState` (disable + `DisabledReason`, Utilities/SchedulerJobIntegrityUtilities.cs:7–18) when the target is missing. Completion message built by `BuildImportCompletionMessage` (:1497).
- **History panel**: per-run rows Started / Duration (`mm:ss` or `hh:mm:ss`) / Result / Error (:642–718); result cell color-coded (orange skipped, goldenrod cancelled, green ok, red fail :689–707). Buttons: **View Output** (disabled for skipped-summary rows, `IsSkippedSummary` :914) and **Clear History** (confirm → `DeleteAllHistory` :1253–1267). Double-click row = View Output (:1000).
- **View Output** (:1387–1418): `JobHistoryService.LoadRunPayload(jobId, runFileName)` → `RunOutputViewerDialog`.

### 2. Job authoring — `JobEditorDialog` (modal, 5 tabs)
Entry: JobListDialog New/Edit (:1035, :1348). Works on a JSON deep clone of the job (`JobEditorDialog.cs:144–152`); Cancel discards everything; result surfaced via `Result` property (:117).

- **General tab** (:341–437): job name; target type radios Single Preset / Preset Folder / Custom Preset; target combo populated alphabetically from `PresetManager.Presets`/`Folders` (:563–581); schedule type combo `None (Manual Only)` / `Recurring (Cron)` / `One-Time` (index-mapped to `ScheduleType`, :1946–1954); cron panel hosting `CronBuilderControl` and a one-time `DateTimePicker` (yyyy-MM-dd HH:mm, up-down, defaults now+1h :494–499) occupying the same y-position, only one visible (:479–505). Custom Preset hides the target combo and shows an info label (:636–659). Significant manual layout-resync code for the cron panel (`RefreshCronPanelLayout` :507–561, `UpdateGeneralTabLayout` :670–696).
- **Content tab** (:439–460): full `ScintillaScriptEditorControl` for job-local ("Custom Preset") YAML/plain commands with autocomplete (`ScriptAutocompleteProvider` fed host-grid column names :594–601), `YamlSshSyntaxHighlighter`, `ScriptEditorValidationService`, and `{{column}}` tooltip resolution from the first/current host row (:603–623). Read-only unless target type is Custom Preset (:661–668).
- **Hosts tab** (:702–1050): a full per-job host grid mirroring the main grid UX — toolbar (Import CSV, Copy from Main Grid, Add Row, Remove Selected, Add/Rename/Delete Column), context menu, protected non-deletable/non-renamable `Host_IP` column (`HostGridUtilities.IsProtectedHostColumn`), live host count label, row-number painting, custom selection painting, type-to-edit (`EditProgrammatically` + KeyPress begins edit :1801), Ctrl+A/C/V and Delete clipboard handling via `HostGridUtilities` (:1818–1847), column reorder honored via `DisplayIndex` ordering at extraction (:827–834). CSV import requires `Host_IP` column (:1861–1888). Copy-from-main uses delegates `getMainGridRows/Columns` supplied by Form1 (`HostGridUtilities.BuildSchedulerCopySnapshot(dgv_variables)`, Form1.cs:15181–15190).
- **Credentials tab** (:1056–1198): four modes — Inherit from app, Stored (Windows Credential Manager), Per-host grid columns (`username`/`password`), Vault (path `profile@path or path[#usernameKey,passwordKey]` + default-profile combo populated from `config.Vault.Profiles` :1416–1432). Stored mode loads existing username + has-password flag from CredMan on open (`LoadStoredCredentials` :1464–1489, target = `CredentialTargets.JobPasswordTarget(job.Id)`), password box placeholder "Leave blank to keep the stored password", note text from `SchedulerJobIntegrityUtilities.FormatStoredCredentialNote`.
- **Advanced tab** (:1204–1325): Folder Execution group (Sequential/Parallel + Stop on first preset failure — enabled only for Folder target type, :1319–1324); per-job **command timeout override** (1–300 s) and **connection timeout override** (5–120 s) with inherited-source guidance labels ("Inherited: preset 'X' timeout (N sec)" / "app default command timeout", :1496–1550) seeded from current config/preset on first check; History Retention overrides — max runs (1–1000, default 50) and retention days (1–365, default 30).
- **Save** (`ValidateAndSave` :2012–2138): all validation delegated to `JobEditorValidator.ValidateAll` (Utilities/JobEditorValidator.cs:215–241 — name ≤100 chars, target selected, custom content non-empty, timeout ranges, cron via `InputValidator.ValidateCronExpression`, one-time future, ≥1 host with `Host_IP`, per-host username/password column + per-row completeness, stored username, vault path non-empty). Stored credentials persisted to CredMan inside the dialog (`TryPersistStoredCredentials` :1964–2010; requires password the first time, reuses stored secret on blank). Save computes `TargetContentHash` (preset) or `FolderPresetHashes` per folder preset via `ContentHasher` for drift tracking (:2077–2099), stamps `ModifiedUtc`, sets `HasDriftWarning = false` ("legacy compatibility", :2133).

### 3. Cron authoring — `UI/CronBuilderControl`
Embedded in JobEditorDialog's General tab; `public sealed UserControl`, designed to be testable (static helpers `BuildExpressionFromDropdowns`/`TryParseToDropdowns`/`GetPresetExpression` :695–755 + internal item arrays).

- 10 preset buttons (Every 5/15/30 min, Hourly, Daily midnight, Daily 3 AM, Weekdays 9 AM, Weekly Monday, Monthly 1st, Quarterly) — comment says "Locked by user decision in RESEARCH.md" (:19).
- Five dropdowns (Minute/Hour/Day-of-month/Month/Day-of-week) with curated values incl. `*/n` steps, `L`, `1-5`, `0,6`, plus a `Custom` sentinel; bidirectionally synced with an editable raw expression textbox (`_suppressSyncEvents` reentrancy guard). Any field not representable → all-`Custom` (:529–558).
- Live human-readable description + next-run preview + inline red validation via injected `SchedulingService` (`SetSchedulingService` :637; `ValidateCronExpression`, `GetDescription` (CronExpressionDescriptor), `GetNextRunLocal` (Cronos)). Without service injection it degrades to echoing the raw expression (:591–600).
- Fully measured custom layout (`RefreshMeasuredLayout` :332–401) that recomputes its own `Height`/`MinimumSize` — the reason JobEditorDialog needs its `RefreshCronPanelLayout` dance.
- `CronExpressionChanged` event fires on every path (preset/dropdown/raw).

### 4. Job run output viewer — `RunOutputViewerDialog`
Entry: JobListDialog View Output / history double-click (:1416). Displays `JobRunPayload` per-host output.

- Host dropdown with status suffix `(OK | FAIL | CANCELLED)` and label support (`Label`, `LabelReplacesAddress` from `JobHostOutput`, :228–239).
- Read-only `RichTextBox`, Consolas 9.5, no word wrap.
- In-output find: Find button or Ctrl+F toggles a search bar; Enter = next, Shift+Enter = previous, Esc closes; wrap-around with "Wrapped"/"Not found" status (:302–387).
- Copy All copies the **currently selected host's** text to clipboard (:276–300).
- "No output available" / "(no output captured for this host)" empty states.

### 5. Manual-run execution forensics — `ExecutionDetailsDialog`
Entry: Form1 main-window history list ("View Execution Details", `Form1.ViewExecutionDetails` Form1.cs:14392–14418; per-host scoped variant :14420–14444 passes `hostAddressFilter` + scoped output). This is the **manual/preset run** detail viewer (HistoryStorageService payloads), distinct from the scheduler's RunOutputViewerDialog.

- 5 tabs: **Summary** (preset name/type, outcome, folder info, start/end/duration, environment, host success/cancel/fail counts, executed preset list, full command text, :366–419); **Hosts** (host/status/timestamp grid); **Settings** (environment, username, command+connection timeouts, pooling, run mode); **Context** (per-host `{{variable}}` snapshot grid, "(no variables)" placeholder); **Interactive** (grid of `InteractiveTerminalSessionDetails` — session #, host, mode, started/ended, close reason, completed — over a transcript pane in a split container with one-shot default layout :331–364).

## Observed gaps & quirks

### Functional gaps / dead affordances
1. **Multi-job export is unreachable.** Jobs grid is `MultiSelect = false` (JobListDialog.cs:303) yet `GetSelectedJobs` (:783–812), export filename logic ("exported-jobs" for >1, :1154) and `ExportToFile(selectedJobs…)` are all plural-aware. A user can only ever export one job at a time; the bulk path is dead code.
2. **`unsupportedInteractivePresets` is never supplied in production.** Both Form1 call sites construct `FolderExecutionDialog` without the parameter (Form1.cs:12286, 12850), so the "(unsupported interactive command)" marking/default-uncheck never fires. Also, even when marked, nothing prevents the user from re-checking an unsupported preset (`LstPresets_ItemCheck` only updates counts, FolderExecutionDialog.cs:254–261).
3. **No job-history retention feedback loop in the UI**: per-job `MaxHistoryRuns`/`HistoryRetentionDays` overrides exist in the editor, but the history panel offers no paging, no count, no "showing N of M", and no per-run delete — only nuke-all "Clear History" (JobListDialog.cs:1253).
4. **No search/filter/sort persistence in the job dashboard.** `RefreshJobList` always rebuilds ordered by `Name` (:504); any header sort the user applies is wiped within 5 seconds by the timer. No filter box despite the grid being the primary management surface.
5. **RunOutputViewerDialog**: "Copy All" copies only the selected host (misleading label); no save-to-file, no combined all-hosts view, no match-count/highlight-all/case-toggle in search. First Shift+Enter after a forward find re-finds the *current* match (reverse range ends at `_lastSearchIndex = index+len`, :337–345) before reaching the previous one.
6. **ExecutionDetailsDialog is `FormBorderStyle.FixedDialog`** (ExecutionDetailsDialog.cs:60) yet sets `MinimumSize` and anchors everything for resize — the dialog can never be resized, so long transcripts/commands are stuck in a 980×680 window.
7. **Editor lacks any "what will run" preview/test affordance** — no dry-run, no "run now" from the editor, no link to the Flow Canvas for custom-preset YAML, and the Content tab help text is the only hint that Folder/Preset jobs ignore it.
8. **One conflict policy on import**: name conflicts are silently auto-renamed by `PrepareImport`; there is no overwrite/replace/skip choice in `ImportPreviewDialog`, and the preview shows no job content (hosts count, credential mode) for vetting before commit.

### Error handling / consistency weak spots
9. **Orphaned Credential Manager secrets**: `JobEditorDialog.TryPersistStoredCredentials` writes the secret keyed by `_editingJob.Id` *before* the dialog returns (JobEditorDialog.cs:2060–2064); the caller's `_jobStorage.Save` can then fail (JobListDialog.cs:1043–1052), leaving a stored credential for a job that never persisted. Duplicate flow got a rollback (:1295–1308) but New/Edit did not.
10. **`OnRunNowClick` is `async void` with no try/catch** (JobListDialog.cs:1061) — an exception from the run-now delegate escapes to the WinForms unhandled-exception path.
11. **Delete confirmation under-communicates** (:1377–1379): "Delete job 'X'?" silently also deletes all run history and the stored CredMan credential.
12. **VB `Interaction.InputBox` for host-column add/rename** (JobEditorDialog.cs:959, 995) — unthemed (breaks dark mode), inconsistent with `DialogTheme` everywhere else, and a `Microsoft.VisualBasic` dependency for two prompts.
13. **Destructive grid replaces without confirmation**: Hosts-tab "Import CSV" and "Copy from Main Grid" wholesale replace existing rows/columns (`ApplyHostGridSnapshot` :1882, :1907) with no warning or merge option.
14. **`ClearHistoryForJob` has no error handling** (:1334–1338) while every neighbor wraps storage calls in try/catch; `JobHistoryService.DeleteAllHistory` swallows internally, but the asymmetry is fragile.
15. **Vault path validated only for non-emptiness** (`JobEditorValidator.ValidateVaultCredentials`, Utilities/JobEditorValidator.cs:177–186) — no format check against the documented `profile@path[#userKey,passKey]` grammar; typos surface only at run time.
16. **Skipped-summary detection duplicated**: `IsSkippedSummary` requires `SkippedRunCount > 0` (:914–915) but `GetSkippedRunCount` clamps to ≥1 for any `WasSkipped` (:917–918) — a skipped record with count 0 renders "SKIPPED" yet stays viewable, an inconsistent edge.

### Performance / hardcoded values
17. **5-second full-rebuild polling** (JobListDialog.cs:179) on top of event-driven refresh: every tick clears/rebuilds both grids and calls `GetRunsForJob` (history index file load) once per job for Last Result (:757) plus once for the selected job's history — disk I/O scales linearly with job count every 5 s while the dialog is open, and is redundant with the three change events already wired.
18. **Per-job command timeout override hard-capped at 300 s** (`JobEditorValidator.MaxCommandTimeoutOverrideSeconds`, Utilities/JobEditorValidator.cs:13) — long-running YAML script jobs (a core use case) cannot override beyond 5 minutes, and `ClampNumericValue` silently clamps a larger inherited app/preset timeout into range when seeding (:1501–1515).
19. **Hardcoded values worth flagging**: `MaxParallelHosts = 100` (FolderExecutionDialog.cs:12); refresh interval 5000 ms (JobListDialog.cs:179, mirrored at Form1.cs:15143); JobListDialog splitter fixed at 60% with no persistence (:157); FolderExecutionDialog is a fixed 420×580 form with absolutely-positioned controls and two 94-px-tall lists regardless of preset/host counts (:67–110) — 20 hosts means scrolling a 4-row box; literal grey `Color.FromArgb(108,117,125)` repeated across JobEditorDialog/CronBuilder instead of a DialogTheme token (JobEditorDialog.cs:1125, 1147, 1187; CronBuilderControl.cs:301, 313).
20. **`FolderExecutionOptions.SelectedHostIndices` is index-based** against the host list snapshotted at dialog-open (FolderExecutionDialog.cs:343; consumed Form1.cs:12297, 12872) — correct today because the row list is captured, but a fragile contract (any upstream reorder/filter between capture and apply silently targets wrong hosts).
21. **Grammar/polish**: "Run 1 Presets" button caption (FolderExecutionDialog.cs:353); JobEditorDialog `MaximizeBox = false` despite `Sizable` border (:284–286); `_btnEditJob` et al. are nullable fields assigned in `BuildToolStrip` with null-guard `SetEnabled` — construction-order defensiveness instead of non-null design.
22. **Drift-warning lifecycle is one-way**: every editor save sets `HasDriftWarning = false` (JobEditorDialog.cs:2133) and recomputes content hashes, but no dialog in this subsystem ever *displays* a drift warning — the flag/hashes are written here and only consumed elsewhere (scheduler side), so a user editing in this UI never sees that their job's preset content changed underneath it.
23. **CronBuilderControl silent-set hazard**: the `CronExpression` setter early-returns when `_suppressSyncEvents` is true (UI/CronBuilderControl.cs:95) — a programmatic set during a sync is silently dropped rather than queued; benign today, trap for future wiring.
