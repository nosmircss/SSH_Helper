## Observed gaps & quirks

### Security
1. **Plaintext passwords persisted to config when Credential Manager is unavailable** — `BuildApplicationState` (14744–14751) only blanks `password` cells when `useCredentialManager`; otherwise full passwords land in `config.json`'s compressed `SavedState`. Same asymmetry on restore (14818–14834 migrates only when manager available).
2. **Password exposed as a script variable** — `GetHostConnections` puts the resolved password in `host.Variables["password"]` (13368–13371), so `{{password}}` interpolates into commands/output (secret-echo risk; matches the standing audit theme).
3. **Credential Manager writes as a read-path side effect** — `GetHostConnections` stores the grid password into the Credential Manager *during every execution enumeration* (13349–13352), not at an explicit save point.
4. **Preset export to clipboard** (10660) — encoded preset (potentially containing embedded secrets in commands) silently placed on the OS clipboard with no warning.

### Error handling / correctness
5. **Connection test cannot be cancelled** — `_connectionTestCts` is created (8899) and `OperationCanceledException` handled (8949), but no UI path calls `Cancel()`; long timeouts × many hosts = unstoppable test run. Also `ApplyConnectionTestCellResult` is invoked even when `hostIpColIndex == -1` (8935, the `>= 0` guard only covers the "Testing..." overlay).
6. **Vault lookups are synchronous on the UI thread** — `vaultCredentialProvider.TryGetPassword` runs inside the `GetHostConnections` iterator (13332–13343), which is materialized via `.ToList()` on the UI thread in `ExecutePresetOnRowsAsync` (12277); N hosts with `vault_path` = N sequential network calls freezing the form before execution starts.
7. **Folder runs ignore per-preset timeouts** — `ExecuteFolderWithOptionsAsync` uses "first preset's timeout or config default" for the entire folder (12916), so a slow preset later in the folder inherits an unrelated timeout.
8. **Folder runs only see direct children** — `ExecuteFolderPresetsAsync` uses `GetSortedPresetsInFolder(folderName, ...)` (12837), which is exact-folder only (comment at 10981), while folder *delete* counts descendants (8125–8126). Running a parent folder silently excludes subfolder presets; no indication in the dialog.
9. **`PasteFromClipboard` splits rows on `"\r\n"` only with `RemoveEmptyEntries`** (9612) — bare-LF clipboard data (Unix/browser sources) collapses to one row; intentionally blank rows are dropped, shifting subsequent data up.
10. **`DeleteHistoryEntry` unconditionally clears the live output pane** (14373) even though the deleted entry may not be the one displayed; `DeleteAllHistory` same (14389) — arguably correct there.
11. **InputBox cancel-vs-empty ambiguity acknowledged but unresolved** — `PromptForImportDestination` (10880–10885) admits Cancel and empty are indistinguishable, so pressing Cancel at the folder-name step imports to root anyway.
12. **`UpdateHostColumn` updates only the first matching row** (`break` at 14212) — duplicate host entries (same IP:port across rows) silently miss script-driven `set-column` updates.
13. **Modal error dialogs from background completion paths** — history-save failures throw modal `DialogTheme.Show` inside `Invoke` during run teardown (13015, 14246), which can interleave with `SetExecutionMode(false)` and block the UI thread mid-cleanup.
14. **History/host output exports use bare `File.WriteAllText`/`StreamWriter`** (8832, 14279, 14308) — fine for user-chosen export targets but inconsistent with the project's atomic-write convention; a failed write mid-`SaveAllHistory` leaves a partial file.
15. **Step-index fallback can mis-attribute step events** — `TryResolveCanvasNodeId` (13788–13808) maps by top-level step index when the path map misses; for scripts edited since the map was built, events can highlight the wrong block (logged, not surfaced).
16. **`ExecutePresetOnRowsAsync` reuses a stale node map** — when `_nodeToStepPathMap` is already populated it is preferred over a fresh `BuildNodeIdToStepPathMap(commandText)` (12333–12335); if the YAML changed without the canvas re-applying, the map and script can diverge.

### Consistency / UX
17. **Two different folder-delete experiences** — context menu (8115) offers delete-presets vs move-presets-to-parent; toolbar button (8196) only offers delete-everything. Same operation, different affordances.
18. **Four direct `Microsoft.VisualBasic.Interaction.InputBox` call sites bypass the test seam and theming** — `ctxRenameFolder_Click` (8093), `AddColumn` (9391), `RenameColumn` (9419), `PromptForImportDestination` (10875) call VB InputBox directly while `ShowInputBox` (11304) exists precisely to wrap it (`_inputBoxPromptOverrideForTests`); VB InputBox also ignores `DialogTheme` dark mode.
19. **Preset-delete undo is fragile by design** — nearly every preset/folder mutation (`move` 7959/8017, base-env 7904, add 8076, rename 8107, favorite 11961/11995, import 10748/10824, save 10216) calls `ClearPresetDeleteUndoHistory()`; users get one undo that evaporates on any subsequent action, with no visual cue beyond the menu text.
20. **Folder rename has no undo** (8103–8108) while delete does — and rename failure only reports "name already exists" regardless of the actual `RenameFolder` failure cause.
21. **Preset filter searches names only** — `PresetMatchesFilter` (9080) is a name-contains check; no command/content search in a tool whose presets are scripts.
22. **Find-in-output is minimal** — substring only (`BuildMatchList` 14583): no regex, whole-word, or highlight-all; matches are recomputed against `txtOutput.Text` (already CRLF-normalized), and `RecreateOutputTextBoxIfNeeded` swaps the control, silently invalidating selection state.
23. **Ctrl+S does nothing outside the script editor** (14454–14460) — no save shortcut for the CSV grid despite the grid having dirty tracking.
24. **Hardcoded status colors** in owner-drawn history host list (8566–8571: `Color.FromArgb(40,167,69)` etc.) and folder icon gold (8760) — outside the theme color constants block (2829–2858).
25. **Connection-test selection semantics** — "Test Connection(s)" tests *all checkbox-checked rows* and only falls back to the right-clicked row when none are checked (8882–8894); right-clicking a specific host while others are checked tests the others, not the one clicked.
26. **`SaveAllHistory` hydrates every payload sequentially on the UI thread** (14309–14325) with no progress indication — large histories will freeze the form.
27. **Forced GC on history navigation** — `RunHistorySwitchGc` fires on every entry switch (8330–8334); aggressive and unusual, presumably masking payload-size pressure rather than fixing it.
28. **`ShowJobListDialog` builds the grid snapshot twice** — both accessor lambdas call `HostGridUtilities.BuildSchedulerCopySnapshot(dgv_variables)` independently (15183/15188), doing duplicate full-grid copies and risking rows/columns from *different* snapshots if the grid changes between calls.
29. **Scheduler lock never re-acquired** — `_schedulerTimerEnabled` is decided once at startup (15092); if the lock-owning instance exits, this instance stays "Scheduler paused" forever (status text at 130/15216) with no retry timer or manual takeover affordance.
30. **Scheduler status recomputes cron next-runs for all jobs every 5 s** (15143, 15224–15241) — fine at small scale, wasteful with many jobs; interval hardcoded.
31. **`CleanupSchedulerServices` doesn't unsubscribe** the `JobsChanged` lambda (15078) or `JobHistoryService.SubscribeTo` hookup — harmless at process exit but inconsistent with the explicit unsubscribes for `JobCompleted`/`JobStateChanged` (15338–15339).

### Dead/vestigial code
32. **`tsbPassword_Click` is an empty stub** (15351–15354).
33. **Dead debug block in `SaveConfiguration`** (14653–14658) — builds a `folderStates` string whose only consumer is a commented-out `DialogTheme.Show`; allocates on every save when debug mode is checked.
34. **`ExecutePresetOnRowsAsync` branch duplication** (12381–12452 vs 12457–12509) — two nearly identical ~70-line blocks for details/history/cancel/error handling differing only in the execute call; classic drift hazard (e.g., a future fix applied to one branch only).

### Performance notes (working as intended but worth knowing)
35. `PasteFromClipboard` (9604–9786) is the most heavily hand-optimized region (WM_SETREDRAW, handler detach, off-grid row building) — any change to grid event wiring must respect the re-attach in its `finally` (9744).
36. `RecreateOutputTextBoxIfNeeded` (14086) destroys/recreates `txtOutput` past 500K chars — code holding a reference to the old control (e.g., a future feature caching `txtOutput`) will silently target a disposed control; `_scrollbarThemedControls` is correctly updated (14123).
37. `SaveCsvToFile` (9310–9325) re-evaluates the lazy `columns` enumerable per row and does a `Columns[c.Name].Index` lookup per cell — O(rows×cols) indexer churn on large grids.
38. `UpdateRunButtonText` (11290–11295) allocates a `Graphics` per call to measure text (called on every checkbox change via selection-count updates).
