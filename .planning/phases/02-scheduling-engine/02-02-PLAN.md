  <action>
    Create UI/CronBuilderControl.cs as a `public sealed class CronBuilderControl : UserControl`. This is a code-only control (no designer file needed -- build layout programmatically in constructor, matching project conventions where dialogs build their own layout).

    **Layout structure (top to bottom):**

    1. **Preset buttons row** -- FlowLayoutPanel at top with compact buttons for each preset template. Button text is the label (e.g., "Every 5 min"). Clicking a preset fills all dropdowns and updates everything.

    2. **Dropdown selectors row** -- 5 labeled ComboBoxes in a TableLayoutPanel:
       - Minute: Items = "*", "0", "*/5", "*/10", "*/15", "*/30" plus "0"-"59" individual values
       - Hour: Items = "*", "0"-"23", "*/2", "*/3", "*/4", "*/6", "*/8", "*/12"
       - Day of Month: Items = "*", "1"-"31", "*/2", "L" (last)
       - Month: Items = "*", "1"-"12" (or "Jan"-"Dec"), "*/2", "*/3", "*/6"
       - Day of Week: Items = "*", "0"-"6" (or "Sun"-"Sat"), "1-5" (weekdays), "0,6" (weekends)
       - Each dropdown also has a "Custom" entry (selected when raw field has a value that doesn't map to a single dropdown item)

    3. **Raw expression row** -- TextBox showing the assembled or typed cron expression. Bidirectional sync with dropdowns using `_suppressSyncEvents` guard flag to prevent infinite loops.

    4. **Description label** -- Shows human-readable text from SchedulingService.GetDescription(). Format: "0 3 * * * -- Every day at 3:00 AM" (per user decision).

    5. **Next-run preview label** -- Shows next occurrence from SchedulingService.GetNextRunLocal(). Format: "Next run: 3/15/2026 3:00 AM" (user's local time, per user decision). Shows "Next run: --" when invalid.

    6. **Validation label** -- Shows error text (red) when expression is invalid. Hidden when valid.

    **Public API:**
    - `string CronExpression { get; set; }` -- gets/sets the current expression. Setting triggers full UI update.
    - `event EventHandler? CronExpressionChanged` -- fires on any expression change.
    - `void SetSchedulingService(SchedulingService service)` -- injects the service dependency.
    - `void ApplyTheme(bool darkMode)` -- applies DialogTheme colors.

    **Bidirectional sync implementation:**
    Use `private bool _suppressSyncEvents` flag. Check at start of every change handler. Set true before programmatic updates, false in finally block. Three sync paths:
    - Preset click -> set all dropdowns -> triggers dropdown-change path
    - Dropdown change -> build expression from 5 dropdowns -> update raw text + description + next-run
    - Raw text change -> try parse to individual fields -> update dropdowns (or set "Custom") + description + next-run

    **Complex expression handling (per RESEARCH.md pitfall 6):**
    When raw text contains a value for a field that doesn't match any dropdown item, set that dropdown to "Custom" (disabled appearance). The raw text field is always the source of truth. Description label provides clarity for complex expressions.

    **Theme support:**
    Constructor accepts no theme arg. ApplyTheme(bool darkMode) can be called after construction. Uses DialogTheme colors for background, text, input, borders. Preset buttons use accent color.

    **Tests in SSH_Helper.Tests/UI/CronBuilderControlTests.cs:**
    Test the logic methods (BuildExpressionFromDropdowns, TryParseToDropdowns, preset application) without requiring a running UI. Extract the expression-building and dropdown-parsing logic into internal static or testable methods. Use `[assembly: InternalsVisibleTo("SSH_Helper.Tests")]` (already exists in the project).
